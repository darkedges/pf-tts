# Authenticated Application UI Plan

## Outcome

Provide a local-lab browser application where a user authenticates at
PingFederate, invokes approved MCP tools through the existing delegated
identity flow, and inspects a live, selectable, transaction-correlated audit
trail. The interaction workspace uses the left two-thirds of the viewport and
the audit trail uses the right third.

## Trust boundaries

### Browser to web application

The browser is untrusted. It receives only an opaque, cryptographically random,
HttpOnly, Secure, SameSite session cookie. It never receives the subject access
token, actor JWT-SVID, transaction JWT, OAuth client secret, PKCE verifier, or
service credentials. Browser-supplied user, agent, workload, transaction, and
audit identifiers are never authoritative.

### Web application to PingFederate

The web application is a backend-for-frontend (BFF) and a separately attested
SPIFFE workload. Login uses Authorization Code with PKCE and a
PingFederate-hosted authentication page. The BFF validates exact redirect URI,
state, nonce, issuer, audience, signature, and token times before creating a
session. PingFederate credentials are entered only into PingFederate.

The lab must add a dedicated browser OAuth/OIDC client. It must not reuse the
development resource-owner-password client or the token-exchange client.

### Web application to delegated service flow

The BFF keeps the user's subject token only in bounded server-side session
memory for the local lab. For every interaction it obtains a JWT-SVID and
performs the existing RFC 8693 exchange. The resulting short-lived transaction
token is verified before the request is sent to the gateway over SPIFFE mTLS.
The original user token never reaches the gateway or downstream services.

The BFF has its own identities:

```text
AgentID:  urn:agent:web-app
SPIFFEID: spiffe://example.org/agent/web-app
```

PingFederate and OPA must bind that pair through trusted configuration. The
browser cannot choose or override either value.

### Services to audit collector

Container stdout remains a safe operational sink, but the UI requires a
queryable audit collector. Each workload submits typed, bounded audit records
to the collector over SPIFFE mTLS. The collector authenticates an exact
allowlist of service SPIFFE IDs and never accepts caller identity from request
fields. Audit records contain allowlisted metadata and redacted summaries, not
raw HTTP headers or arbitrary bodies.

The UI queries audit data through the BFF. Results are filtered server-side by
the authenticated user ID. Knowing or guessing another TransactionID must not
grant access.

## Proposed components

```text
Browser
  | Authorization Code + PKCE redirect
  v
PingFederate

Browser -- opaque session --> web-app BFF (SPIFFE: agent/web-app)
                               | JWT-SVID + subject token exchange
                               | transaction JWT + SPIFFE mTLS
                               v
                            MCP gateway --> MCP server --> API
                               |              |             |
                               +---- typed audit over mTLS --+
                                              |
                                              v
                                        audit collector
                                              |
                         user-filtered query via web-app BFF
                                              |
                                              v
                                           Browser
```

Use Go's embedded static assets for the first UI so the repository does not
need a Node runtime or a second application framework. Keep browser assets
separate from handlers so a richer frontend can replace them later.

## Data model

Add a separate interaction-detail model rather than placing payloads in the
existing credential-safe `audit.Event`:

- interaction ID generated by the BFF;
- verified TransactionID;
- verified user ID;
- event timestamp and ordered hop;
- event type, target, decision, and reason code;
- verified logical agent and SPIFFE identities;
- allowlisted request summary: protocol method, tool name, purpose;
- allowlisted response summary: status, result type, bounded safe fields;
- duration and correlation metadata.

Never store authorization headers, cookies, codes, token responses, client
secrets, private material, PKCE values, raw tool arguments, or unrestricted
request/response bodies. Maximum event count, field length, and retention must
be configured and bounded. The first local implementation may use an in-memory
ring store; durable production storage is a separate design decision.

## Browser API

- `GET /login` starts the server-side state/nonce/PKCE transaction.
- `GET /oauth/callback` validates the response and creates the session.
- `POST /logout` revokes local session state and clears the cookie.
- `GET /api/session` returns safe display identity.
- `POST /api/interactions` invokes one allowlisted tool and purpose.
- `GET /api/interactions` lists only the current user's interactions.
- `GET /api/interactions/{id}` returns that user's ordered, redacted hop detail.
- `GET /api/audit/stream` provides a same-user event stream, with polling as a
  simple fallback.

All state-changing endpoints require a session and CSRF protection. Apply
explicit timeouts, body limits, content types, security headers, and no-store
cache policy to authentication/session responses.

## Ordered implementation tasks

### UI-01 — Typed configuration and boundaries

Status: complete and applied to the local PingFederate lab.

- Add web, OIDC, session, and audit-collector configuration.
- Add exact redirect URI and issuer validation.
- Register distinct SPIFFE IDs for web-app and audit collector.
- Add failure tests for missing/duplicate identities, insecure callback URLs
  outside explicit local development, unbounded retention, and invalid cookie
  settings.

### UI-02 — PingFederate browser client

Status: complete.

- Add a dedicated Authorization Code + PKCE/OIDC lab client and authentication
  policy mapping through Terraform.
- Keep secrets outside Git and preserve Terraform encrypted-secret drift rules.
- Test invalid redirect URI, absent PKCE, wrong client, and unintended grant
  types.

### UI-03 — BFF login and session

Status: complete.

- Implement start, callback, session, CSRF, and logout handlers.
- Store pre-authentication and authenticated sessions server-side with bounded
  TTL and cryptographically random IDs.
- Verify ID-token signature, issuer, audience, nonce, and time claims before
  trusting the subject.
- Test forged/replayed state, wrong nonce, issuer, audience, signature,
  expiration, session fixation, CSRF, and cookie leakage.

### UI-04 — Interactive delegated invocation

Status: complete; the exact web-app binding is applied to the local
PingFederate lab. Live browser validation remains in UI-07 after the runnable
web workload and interface are added.

- Extract the reusable exchange-and-invoke logic from the CLI runner without
  weakening its verification.
- Bind the web workload to `urn:agent:web-app` in PingFederate and OPA.
- Allow only server-configured tool/purpose pairs.
- Test browser-supplied AgentID/workload/target overrides, missing subject
  session, wrong SPIFFE identity, failed exchange, and downstream rejection.

### UI-05 — Queryable audit collector

Status: complete in code. Compose wiring and browser-driven live correlation
remain in UI-07.

- Add a bounded in-memory store and mTLS collector API behind small interfaces.
- Fan out audit events to stdout and the collector; allowed operations fail
  closed when the required audit write fails.
- Enforce exact submitting workload identities and server-derived ownership.
- Test spoofed service identity, oversized/unknown fields, token-shaped data,
  write failure, cross-user lookup, guessed TransactionID, and retention bounds.

### UI-06 — Browser interface

Status: complete in code. Container wiring, trusted local browser certificate,
and browser-driven validation remain in UI-07.

- Build responsive two-column layout with a two-thirds interaction panel and a
  one-third audit panel.
- Provide sign-in/sign-out state, allowlisted tool forms, result display,
  transaction grouping, hop timeline, decision badges, and selectable safe
  request/response detail.
- Keep secrets out of DOM, URLs, browser storage, console logs, and telemetry.
- Add accessibility, keyboard navigation, narrow-screen stacking, empty,
  loading, denied, and unavailable states.

### UI-07 — Complete end-to-end validation

- Extend Compose and SPIRE registration for both new workloads.
- Add a browser-driven live test for PingFederate sign-in, tool invocation,
  four-hop correlation, audit selection, and logout.
- Add failure cases for forged state, unauthenticated invocation, CSRF,
  cross-user audit isolation, direct service calls, and raw-credential leakage.
- Validate fresh local-lab startup, Go tests/vet, Terraform formatting and
  validation, Linux builds, and supported Windows builds.

## Decisions required before implementation

1. The first version will use a Go BFF with embedded HTML/CSS/JavaScript.
2. Local sessions and audit details will be bounded and in-memory; restarting
   the lab clears them.
3. PingFederate will host credential entry; no password form will exist in this
   application.
4. Audit request/response views will be structured summaries, not raw traffic.
5. The web app will be a distinct logical agent and SPIFFE workload rather than
   impersonating the existing demo agent.

These defaults minimize new dependencies and preserve the existing identity
invariants. Any change to them should be reviewed before UI implementation.
